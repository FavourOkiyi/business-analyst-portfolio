# Coming Back to Data: What I Learned in the Analytics Development Lifecycle Bootcamp

Five years ago, I made a career switch — not out of some grand plan, but because I needed a job that could take care of me. Data analytics stayed in the back of my mind the whole time. This year, I decided to close that gap and joined the **Analytics Development Lifecycle (ADLC) Bootcamp by Databyte Analytica**. I expected a refresher. What I got was a fully packed, genuinely modern curriculum that pushed me well beyond what I remembered.

## What Is Data Analytics?

Data analytics is the practice of turning raw data — transactions, user behavior, operational records — into something people can act on. On its own, data is just noise. Analytics finds the signal: the trend, the anomaly, the answer to a question the business actually needs answered.

## The Roles in Data

Data work is an ecosystem, not one job:
- **Data Analysts** answer specific business questions using SQL — from basic queries to joins, aggregations, and window functions — paired with visualization
- **Business Analysts** translate business problems into clear requirements
- **Analytics Engineers** model data (Kimball, dimensional modelling) so it's usable across an organization
- **Data Engineers** build the pipelines and cloud infrastructure behind it all
- **BI Developers** turn validated data into dashboards people can actually use

## The Analytics Development Lifecycle (ADLC)

This was the backbone of the bootcamp — treating analytics as a full discipline, not just "query data, make chart":

1. **Model the data** — structuring raw data using OBT (One Big Table), Kimball methodology, and dimensional modelling, each with different tradeoffs between simplicity and scalability
2. **Build on cloud infrastructure** — using Google Cloud Platform and Lakehouse architecture to store and process data at scale
3. **Validate data quality** — using Dataform to write tests directly into the pipeline, catching bad data before it ever reaches a dashboard
4. **Query and analyze** — writing SQL from the ground up: filtering, joins, and aggregations, then moving into advanced SQL like subqueries, CASE logic, and window functions (RANK(), LAG(), ROW_NUMBER()) to answer layered business questions a simple SELECT can't
5. **Apply analytical frameworks** — moving beyond basic aggregation into Growth Accounting, Cohort Analysis, and LTV (Lifetime Value) modelling, the kind of analysis that actually informs product and business decisions
6. **Visualize and communicate** — using Power BI, including writing DAX measures and building calculated fields, to turn validated data into dashboards that tell a clear, digestible story
7. **Work alongside AI** — this was the most eye-opening part for me. Analysts today don't just write SQL and build dashboards manually; tools like VS Code paired with AI assistants and LLMs let you write and debug complex queries faster, catch logic errors before they reach a report, and even scaffold entire dashboards more efficiently. We also built Copilot agents to support data-driven workflows directly. It reframed AI not as a shortcut, but as another tool in the analyst's kit — the same way SQL or Power BI is.
